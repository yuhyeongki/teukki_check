# 활동 자기평가 · 확인 시스템

## 설치 안내

구성: **버셀(화면·로그인)** → **앱스스크립트(처리)** → **구글 스프레드시트(저장)**

| 파일 | 넣을 곳 |
|---|---|
| `apps-script/Code.gs` | 스프레드시트의 Apps Script 편집기 |
| `web/index.html`, `web/config.js` | 버셀 |

## 1. 버셀 주소 먼저 만들기

1. 버셀에서 이 GitHub 저장소를 가져옵니다.
2. **Root Directory**는 `web`, 프레임워크는 `Other`로 두고 빌드 명령은 비워 둔 채 배포합니다.
3. 학생이 접속할 고정 주소(예: `https://내프로젝트.vercel.app`)를 적어 둡니다.

## 2. OAuth 클라이언트 ID 만들기

1. [Google Cloud Console의 클라이언트 페이지](https://console.cloud.google.com/auth/clients)에서 프로젝트를 만듭니다.
2. 브랜딩(앱 이름, 지원 이메일)을 설정하고 대상은 **외부**로 선택합니다.
3. 게시 상태가 `테스트`라면 **앱 게시**를 눌러 둡니다.
4. 클라이언트 만들기 → 유형 **웹 애플리케이션**
5. **승인된 JavaScript 원본**에 1번의 버셀 주소를 넣습니다. 끝에 `/`나 경로를 붙이지 않습니다. 리디렉션 URI는 비워 둡니다.
6. 만들어진 클라이언트 ID(`…apps.googleusercontent.com`)를 복사합니다.

## 3. 스프레드시트와 앱스스크립트

1. 새 구글 스프레드시트를 만듭니다. **누구에게도 공유하지 않습니다.**
2. `확장 프로그램 → Apps Script`를 열고 `Code.gs` 내용을 모두 붙여넣습니다.
3. 맨 위 `CONFIG`의 두 값을 바꿉니다.
   - `CLIENT_ID`: 2번에서 복사한 값
   - `ADMIN_EMAIL`: 교사용으로 로그인할 본인 구글 계정
4. 저장한 뒤 함수 목록에서 `setup`을 골라 **실행**하고 권한을 승인합니다. 시트 5개가 생깁니다.
5. `배포 → 새 배포 → 웹 앱`
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** (로그인 확인은 코드가 합니다)
6. 웹 앱 URL(`…/exec`)을 복사합니다. 브라우저로 열었을 때 `API 작동 중`이 보이면 정상입니다.

## 4. 연결

1. `config.js`의 `API_URL`에 웹 앱 URL, `CLIENT_ID`에 클라이언트 ID를 넣고 GitHub에 올립니다.
2. 버셀 재배포가 끝나면 주소에 접속해 `ADMIN_EMAIL` 계정으로 로그인합니다.

## 사용 순서

1. **설정 (안내·탭)**: 안내 문구를 고치고 과목·동아리 탭을 만든 뒤 `설정 저장`. `예시 과목` 탭은 이름을 바꾸거나 삭제합니다.
2. 학생에게 주소를 안내합니다. 학생은 로그인 후 학번·이름으로 등록을 신청합니다.
3. **학생 관리**: 학번·이름·계정을 확인하고 승인 → `변경 저장`. 특정 학생만 볼 탭이 있으면 `그룹` 칸을 탭의 `대상 그룹`과 똑같이 입력합니다.
4. 학생이 자기평가를 작성해 제출합니다. 마감하려면 탭의 `학생 작성 받는 중`을 끕니다.
5. **작성·검토**: 자기평가를 보며 작성합니다. 확인받을 학생만 `이 학생에게 공개`를 켜고 `변경 저장`.
6. 학생이 `이상 없음` 또는 `수정 의견`을 보냅니다.
7. 확인 기간이 끝나면 `전체 비공개` → `변경 저장`.

## 코드를 고쳤을 때

- `Code.gs` 수정: `배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포`. 이렇게 해야 URL이 바뀌지 않습니다.
- 화면 수정: GitHub에 올리면 버셀이 자동 배포합니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 로그인 버튼 오류, `origin_mismatch` | 승인된 JavaScript 원본이 접속 주소와 같은지. 미리보기 주소에서는 로그인되지 않음 |
| `연결에 실패했습니다` | `API_URL`이 `/exec`로 끝나는지, 액세스 권한이 `모든 사용자`인지 |
| `로그인 정보를 확인할 수 없습니다` | 두 파일의 `CLIENT_ID`가 같은지 |
| 교사인데 학생 화면이 나옴 | `ADMIN_EMAIL` 확인 후 새 버전으로 배포 |
| 카카오톡에서 로그인 안 됨 | Chrome 또는 Safari로 열기 |

## 운영할 때 주의

- 학생 개인정보와 작성 내용이 선생님의 스프레드시트에 저장됩니다. 공유 설정을 끄고, 계정에 2단계 인증을 켜고, 사용이 끝나면 삭제하세요.
- 학생에게 수집 항목(구글 계정, 학번, 이름, 작성 내용), 목적, 보관 기간을 안내하세요. 학교의 개인정보·학습지원 소프트웨어 절차가 필요한지도 확인하세요.
- 동시에 처리할 수 있는 요청 수에 제한(30개)이 있습니다. 접속이 몰리면 자동으로 다시 시도하지만, 한 반이 처음 쓸 때는 저장이 잘 되는지 확인하세요.
- 시트를 직접 고칠 때는 첫 행(제목)과 `id`, `tabId`, `version` 열은 바꾸지 마세요.
